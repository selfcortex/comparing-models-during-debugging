# Задача: починить `taskflow.py`

В файле `taskflow.py` — небольшой движок выполнения графа задач (rate limiter, TTL-кэш,
шина событий, DAG, retry, транзакционное хранилище, сериализация с миграциями и сам
`Engine`, который всё это связывает).

Модуль написан с множеством ошибок: от простых до очень неочевидных — логика, граничные
случаи, порядок операций, копирование данных, взаимодействие компонентов, глубина рекурсии,
асимптотика. Часть ошибок проявляется только при совместной работе компонентов.

## Что нужно сделать

1. Найти и исправить **все** расхождения между кодом и документацией в `taskflow.py`.
2. **Docstring'и — это контракт.** Если код и docstring расходятся — прав docstring.
   Читай их внимательно, в каждом контракте есть точные формулировки.
3. Публичный API (имена классов, методы, сигнатуры, формат событий и отчётов) менять нельзя.
4. Только стандартная библиотека Python 3, никаких новых зависимостей.
5. Править можно только `taskflow.py`. Свои тесты писать можно (например, в `tests/`) —
   это даже полезно, но проверять результат будут независимым набором проверок,
   которого у тебя нет.

## Ожидания

- Не ограничивайся очевидными ошибками: проверяй граничные условия, порядок побочных
  эффектов, повторные и вложенные вызовы, большие входы (например, цепочка из 20 000
  задач) и взаимодействие компонентов между собой.
- Исправляй причину, а не симптом. Не «затыкай» конкретные входные данные.
- В конце кратко перечисли найденные ошибки и что ты исправил.
